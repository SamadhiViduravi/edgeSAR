# Data card: EdgeSAR-Reports-1400

Version 1.0, 14 November 2026. Author: Samadhi Dissanayake (Informatics Institute of Technology, Colombo, affiliated with the University of Westminster). Supervisors: Dr. Achala Aponso, Mr. Maninda Edirisooriya.

## 1. What this is
A synthetic set of **1,400 short field reports** from a made-up multi-UAV flood search-and-rescue operation. Each report comes with the list of incidents that are open at that moment and a **gold task record**: the correct decision for a task allocator. The set was built to test how 4-bit quantisation of a small language model changes the decisions it writes (action, sensor, priority) and what that does to a simulated rescue mission.

## 2. Why it was made
No public set exists that pairs free-text rescue reports with a fixed, machine-checkable decision record and a known correct answer. Because the generator chooses the facts first and writes the text second, every gold record is correct by construction. This allows the effect of quantisation to be measured on decisions, not only on perplexity or benchmark accuracy.

## 4. Files and fields
`data/cases.jsonl` (one JSON object per line, UTF-8, LF line endings):

| Field | Meaning |
|---|---|
| `id` | `c0001` to `c1400` |
| `style` | `A` or `B` |
| `split` | `dev` (style A) or `held` (style B). The name `held` is historical: style B was not kept untouched (see section 7, limit 6). |
| `family` | Block id (`A###` or `B###`). The generator numbers every 10 consecutive generated reports as one block, after the random order of kinds is drawn. It is a grouping label for cross-validation, not a group of similar wordings. |
| `type`, `subtype` | Kind of report (CREATE, UPDATE, CLOSE, NO_ACTION) and its sub-kind |
| `source` | UAV1, UAV2, UAV3, Ground team, or Command post |
| `time` | HH:MM, 06:00 to 23:59 |
| `open` | List of open incidents: `id`, `landmark`, `sensor`, `priority` |
| `text` | The report |
| `gold` | The correct decision: `action` (4 values), plus `incident` / `landmark` / `sensor` / `priority` where the action needs them |

Landmarks come from a fixed list of 12 made-up places (for example Temple Junction, North Bridge, Clinic Gate). The decision schema is 4 actions x 3 sensors x 3 priorities, with one incident link.

## 4a. Three complete cases, field by field
Generated by `generator/gen_cases.py` (seed 20261026), function in brackets. The generator first chooses the facts and the correct decision, then writes the text from them.

**c0010** [`make_create`], style A, confirmed sighting
```
{"id": "c0010", "style": "A", "open": [{"id": "I5", "landmark": "School Ground", "sensor": "RGB", "priority": 2}, {"id": "I10", "landmark": "Boat Jetty", "sensor": "ANY", "priority": 1}], "source": "Command post", "time": "13:42", "text": "At Temple Junction: an injured person clinging to a fence. Water is rising fast. Battery at 58 percent.", "gold": {"action": "CREATE_VERIFICATION", "landmark": "Temple Junction", "sensor": "ANY", "priority": 3}, "type": "CREATE", "subtype": "confirmed", "split": "dev", "family": "A059"}
```
The generator picked a free landmark (Temple Junction), a vulnerable person (injured) and a hazard (rising water), and no visibility cue. Rule: priority 3 if a vulnerable person or a hazard is present; sensor ANY when no visibility cue is given. "Battery at 58 percent" is a distractor sentence added with probability 0.25. The open list has two other incidents, so this is a new incident: CREATE_VERIFICATION.

**c0008** [`make_update`], style A, sensor change
```
{"id": "c0008", "style": "A", "open": [{"id": "I5", "landmark": "Boat Jetty", "sensor": "THERMAL", "priority": 1}, {"id": "I7", "landmark": "Hill Road Bend", "sensor": "THERMAL", "priority": 3}, {"id": "I9", "landmark": "Temple Junction", "sensor": "THERMAL", "priority": 3}, {"id": "I12", "landmark": "Clinic Gate", "sensor": "RGB", "priority": 1}], "source": "UAV2", "time": "15:24", "text": "UAV2: at Clinic Gate now. Night conditions. The visible camera cannot see anything there. Radio check ok.", "gold": {"action": "UPDATE_INCIDENT", "incident": "I12", "landmark": "Clinic Gate", "sensor": "THERMAL", "priority": 1}, "type": "UPDATE", "subtype": "sensor", "split": "dev", "family": "A064"}
```
The text says the visible camera is useless at Clinic Gate at night, so the open incident at Clinic Gate (I12, sensor RGB) must be switched to THERMAL; priority stays 1. The incident id I12 is found only by matching the landmark in the open list.

**c0048** [`make_close`], style A, rescued
```
{"id": "c0048", "style": "A", "open": [{"id": "I1", "landmark": "Railway Crossing", "sensor": "RGB", "priority": 2}, {"id": "I3", "landmark": "Fuel Station", "sensor": "RGB", "priority": 2}, {"id": "I7", "landmark": "Clinic Gate", "sensor": "RGB", "priority": 3}, {"id": "I13", "landmark": "Boat Jetty", "sensor": "ANY", "priority": 3}], "source": "Command post", "time": "23:39", "text": "Command post: Railway Crossing is resolved, all rescued.", "gold": {"action": "CLOSE_INCIDENT", "incident": "I1"}, "type": "CLOSE", "subtype": "rescued", "split": "dev", "family": "A038"}
```
Railway Crossing is open as I1, so the report closes I1. The same sentence in `c1327` has Railway Crossing open as I2, so there the gold is I2.

Field meaning: `open` = incidents known at that moment; `source` = who wrote the report; `time` = report time; `text` = the report; `gold` = the correct decision; `type`/`subtype` = which generator branch made it; `split`/`family` = see section 4.

`data/subsets.json`: three id lists used in the study: `all` (1,400), `prompt` (300, used to compare three prompt wordings), `nogrammar` (100, used to test generation without a grammar constraint).
`data/audit_sample.csv`: a blank 60-row sheet for a human to check the gold records (columns "gold looks right? (y/n)" and "your note" are empty).

## 5. How it was made
`generator/gen_cases.py` with `generator/common.py`, fixed random seed, Python standard library only. Word banks and sentence templates for both styles are in the file. Style B uses different words and sentence shapes, so a model or classifier tuned only on style A has not seen the style B wording. Style B was nevertheless examined many times during the exploratory analysis; it is a wording-shift set for exploration, not a clean final test set. Run `python verify_dataset.py` to regenerate the set and compare it with the published file (SHA-256 of the LF-normalised file: `833fafe2fb47af9927603e4aab0cb45031b81999cf38dd796253662f30f0a769`). The version used in the experiments had Windows line endings (SHA-256 `3c51f0b4...c91a`); the records are identical.

## 6. Intended use
Studying how model compression (quantisation), prompt wording and readout changes affect structured decisions, and how decision errors propagate to an allocation simulator. Not for training a deployable rescue system.

## 7. Known limits (read before citing)
1. **Synthetic and template-based.** The wording is far narrower than real field reports. A simple TF-IDF classifier reaches 98.1% on style A wording but only 53.5% on style B, which shows how much of style A is learnable surface pattern.
2. **Gold is correct by the generator's rules, not human-checked.** No completed human label audit is bundled. The blank audit sheet is provided so others can do it.
3. **Small and single-domain.** One language (English), one scenario (flood rescue), 12 landmarks, 140 families. Results do not claim to generalise to other models, tasks or real operations.
4. **Repeated texts.** 125 report texts occur more than once (293 reports in all), always in different family blocks. The same text with a different open-incident list is a different valid input: the report never names the incident id, so the correct answer copies the id (and sometimes the sensor or priority) from the open list. For 16 of the repeated texts the gold record differs for this reason (13 differ only in the incident id). Example: `c0048` and `c1327` both read "Command post: Railway Crossing is resolved, all rescued."; the gold is CLOSE_INCIDENT I1 in one and I2 in the other. Models must read the open incidents, not only the text. Family blocks do not stop wording from recurring across folds.
5. **No human subjects.** No personal data, no real incidents, no real locations.
6. **Style B is not an untouched test set.** The 400 style-B reports were used repeatedly in the development and exploratory analyses (including the wording-shift results). Any claim of generalisation to new wording needs a freshly generated set that is looked at only once.
7. **Gold means the generator's rule, not expert judgement.** Rescue professionals did not check the labels.

## 8. Ethics
All text is machine-generated from templates. It contains no personal data and no real people or places. The hidden vectors and model files are not included (see Licence).

## 9. What is and is not in this package
Included: the reports and gold records; the generator; the full study code (pilot, heads, simulator, Shield, tools, tests); the allocator source used by the simulator (`code/V1/packages/allocation/`); protocols with their SHA-256 hashes; small result files (markdown and JSON).
The package was scanned for passwords, keys and tokens (none found). The author's local folder name (`D:\1 Samadhi UNI\...`) appears in some documents and scripts; they are hash-pinned, so they were left unchanged.
Not included: model weights (Llama 3.2 1B Instruct and its GGUF files are covered by the Llama 3.2 Community Licence and are downloaded separately from the source named in `code/edgesar_pilot/README.md`); extracted hidden-state vectors (derived from those weights); large run logs. The vectors can be regenerated with `code/edgesar_shield/tools/extract_fresh_vectors.py` and `code/edgesar_heads/02_extract.py`.
