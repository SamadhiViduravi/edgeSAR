# EdgeSAR fresh confirmation: protocol (written and hashed BEFORE any fresh vector exists)

Status: FROZEN on 18 Nov 2026. Author: Samadhi V. Dissanayake (with AI assistance, declared). The SHA-256 of this file, of the three scripts and of
the pre-freeze check result are in `FROZEN.sha256`. A copy of both files is uploaded to the shared supervisor Drive folder before the GPU step,
so Google Drive's upload time is an outside timestamp.

## 1. Why

Every mission number so far is development evidence: the same 1,000 style-A reports were reused, the reading position `prefix` was chosen after
the results were seen, and the 100-label comparison was highlighted after it was seen. The strict reviewer's main objection was "no confirmation
on fresh data". This test answers it once, with the analysis fixed first.

## 2. What is fixed now (nothing below may change after this file is hashed)

* **Training data:** the 1,000 development style-A reports of EdgeSAR-Reports-1400 and their SAVED hidden vectors (f16 and Q4_K_M; `end` and
  `prefix`). No fresh report is used for any fitting, selection or threshold.
* **Fitting code and seeds:** exactly the style-B task of `run_ppr2.py` (protocol B of 14 Nov): `ppr_lib.fit_head` (C chosen from
  0.0003 to 3 by 3-fold template-grouped cross-validation), `ppr_lib.Recentre`, `ppr_lib.AffineMap` (lambda chosen on held-out pairs, no labels),
  seed 20262112 (= 20261113 + 999). Scarce-label arms: 100 and 300 labels, 5 independent draws each, draw d uses seed 20262112 + 1000(d + 1)
  (a draw is redrawn until all four actions occur). Text baselines: the pilot rule engine and the pilot TF-IDF + logistic regression fitted on the
  same 1,000 reports.
* **Pre-freeze check (passed):** `fresh_confirm.py --mode check` rebuilt the 14 Nov style-B check with this code. All twelve arms gave records
  identical to the saved predictions (400 of 400 each), and every mission share at L, M and H equalled the saved wording-shift result.
  Replay consistency: 0 violations. Its `results.json` hash is in `FROZEN.sha256`.
* **Scripts:** `gen_fresh.py` (fresh reports), `fresh_extract.py` (GPU vectors), `fresh_confirm.py` (analysis). Hashes in `FROZEN.sha256`.
  `fresh_confirm.py` refuses to run if a hash differs or if a result already exists (one run only).

## 3. Fresh reports

Generated by `gen_fresh.py` with the pilot's own generator functions (`gen_cases.py`, SHA-256 pinned), the pilot class mix (CREATE 25%,
UPDATE 20%, CLOSE 15%, NO_ACTION 40% in four kinds), and no model.

| Set | Wording | Seed | Episodes x reports | Role |
|---|---|---|---|---|
| A | development wording (style A) | 20261118 | 300 x 20 = 6,000 | **primary** |
| B | new wording (style B) | 20261119 | 50 x 20 = 1,000 | secondary (wording shift) |

A report whose (text, open-incident table, gold record) already occurs in the 1,400 development reports or earlier in the file is thrown away and
drawn again. Episode membership is fixed at generation (20 consecutive reports). Known limits, stated now: the language comes from the same
templates (only new draws); some fresh texts are identical to a development text (with a different open table or gold record); their number is
written in `generation_manifest.json`, and a record-accuracy result on the reports whose text is NOT in the development set is reported beside every
accuracy. A smaller code-test generation (150 set-A episodes) was made before this freeze to test the scripts; no model was run on it, and its
input counts were the only thing looked at. The size was then raised to 300 episodes for power (section 8), before any model output existed.

## 4. Vectors (GPU step, on the author's laptop)

`fresh_extract.py` uses the code and settings that made the saved development vectors (`edgesar_heads`: `make_server`, `extract_features`,
prompt P1, llama.cpp b11901, `--embeddings --pooling last -b 1024 -ub 1024`, `-ngl 99`, the audited GGUF files). Models: f16 and Q4_K_M
(Q8_0 is not extracted). Positions: `end` and `prefix`.
**Anchor check:** for each model and position, 20 development reports (c0001, c0051, ..., c0951) are embedded again and compared with the saved
vectors; every cosine must be at least 0.9999. If not, the run stops; no fresh analysis is done until the cause is found and recorded as a deviation.

## 5. Arms (all always commit; same simulator; reading position `prefix` unless marked)

gold (reference); f16p (FP16 reader); rawp (Q4 with the FP16 reader unchanged); recp (recentred); alnp (label-free map); q4p (retrained on 1,000
labels); q4p_n100 and q4p_n300 (retrained on 100 or 300 labels; per episode, the mean over the 5 draws); tfidf; rule; q4p_goldS and alnp_goldS
(gold sensor field substituted, diagnosis only); and at `end`: f16, raw, rec, aln, q4.

## 6. Mission

The `edgesar_shield` simulator and bounded CBBA allocator unchanged (3 UAVs, one with a thermal camera; deadlines 240 / 360 / 480 s for priority
3 / 2 / 1; levels L, M, H with mean gaps 60, 30 and 8 s). Episodes: the fixed 20-report episodes; arrival times from `make_fixed_episodes` with
arrival seed 11 (primary), 12 and 13 (secondary). **Outcome:** missed share = incidents verified late or never / all incidents.

## 7. Primary analysis

Set A, level M, arrival seed 11 (300 independent episodes; every fresh report used once), reading position `prefix`. Paired by episode;
difference in pooled missed share; 95% episode-bootstrap interval (10,000 resamples, seed 7); two-sided sign-flip test. Holm correction over the
four tests at alpha 0.05. A hypothesis is **confirmed** only if its interval excludes 0 in the stated direction AND its Holm-adjusted p < 0.05.

| ID | Comparison (first minus second) | Expected direction | Meaning |
|---|---|---|---|
| H1 | rawp - f16p | > 0 | Moving to Q4 without adapting the FP16 reader causes extra missed incidents |
| H2a | alnp - rawp | < 0 | The label-free map removes part of that harm |
| H2b | q4p - rawp | < 0 | Retraining on Q4 labels removes part of that harm |
| H3 | alnp - q4p_n100 | < 0 | With only 100 Q4 labels, the map misses fewer incidents than retraining |

## 8. Secondary results (reported in full; no confirmatory claim)

S1 alnp - q4p, with non-inferiority judged at margins 0.25 and 0.5 percentage points (upper bound below the margin); S2 alnp - q4p_n300;
S3 alnp - recp; S4 recp - q4p_n100; S5 q4p - f16p; S6 alnp - f16p; S7 tfidf - f16p; S8 tfidf - alnp; S9 rule - alnp; S10 and S11 gold-sensor
substitution; S12 raw - f16 and S13 aln - q4 at `end`; S14 q4p_n100 - q4p; S15 f16p - gold. All at L, M and H, per arrival seed and pooled over
the three seeds (pooled intervals are optimistic), for set A and set B. Whole-record accuracy per arm and set.
Expected precision (development per-episode SD of the paired difference: 2.73 points for map minus all-label retraining, 4.05 points for map
minus 100-label retraining): with 300 episodes the standard error is about 0.16 to 0.23 points (95% half-width about 0.3 to 0.5 points).
H1 (development +3.45 points) should be resolved. H3: about 0.99 power if the true difference equals the development estimate (-1.18 points),
about 0.7 if it is half of it (before Holm). S1 (development -0.15 points) is not expected to be resolved.

## 9. Rules

* One run. Every result is reported, in whichever direction. Nothing is tuned, added or dropped after the vectors exist.
* The run is void if the replay-consistency check reports any violation, or if a hash in `FROZEN.sha256` does not match.
* Any departure from this file is written as a dated deviation next to the results, never edited into this file.

## 10. Not claimed even if every hypothesis is confirmed

Real field reports (the data are synthetic and template-based); a real 2 GB device; the CPU delay inside the mission; other models, other
quantisation recipes or other simulators; that the alignment map is new (it is Duan's method, 2026).
